# Указания для работы с этим репозиторием

Проект: «ИИ Сметчик» — расчёт стоимости ремонтных работ по проектной
документации для компании «Капсула».

## Инварианты, которые нельзя нарушать

Это не стилистические предпочтения, а свойства, ради которых написан код.
Изменение любого из них — продуктовое решение, а не рефакторинг.

1. **Расчёт не привязан к HTTP-запросу.** Веб-сервер создаёт задачу и отдаёт
   статус. Анализ выполняет отдельный процесс воркера. Никогда не переносите
   вызов модели в обработчик запроса и не имитируйте фон таймером.

2. **Состояние задачи живёт в БД.** Не в памяти процесса, не в состоянии вкладки.
   Задача обязана переживать перезапуск любого процесса.

3. **Сессия интерфейса не участвует в жизненном цикле задачи.** Истечение
   сессии не должно останавливать или терять расчёт.

4. **Цена приходит только из БД.** `VolumeClaim` не имеет и не должен иметь
   поля цены. Любой маршрут, принимающий цену от клиента, — уязвимость.

5. **Деньги считает код.** Целые копейки, BigInt, округление половины от нуля.
   Никаких вычислений в числах с плавающей точкой и никаких сумм от модели.

6. **Модель не видит цен.** Ей выдаётся каталог кодов и единиц; она возвращает
   код и объём. Это структурный барьер против prompt injection — не убирайте его.

7. **Неизвестное не превращается в число.** Отсутствие данных идёт в примечания
   как «не включено», а не в смету с придуманным объёмом.

8. **API всегда отвечает JSON.** HTML на месте JSON давал пользователю
   «Unexpected token '<'». Обработчик 404 в `app.ts` единственный и обязан
   различать `/api` и SPA.

9. **Наружу не уходят stack trace, сырые ответы внешних API и секреты.**
   Только `{ code, message, retryable }` из таксономии `shared/errors.ts`.

## Структура

```
src/shared/      конфигурация, ошибки, деньги, логи, криптография
src/db/          схема и миграции
src/jobs/        durable-очередь: захват, аренда, повторы, тайм-ауты
src/domain/
  pricelist/     разбор файлов, слияние редакций, хранение версий
  estimate/      расчёт, проверка полноты, сохранение, экспорт xlsx
  extraction/    схема ответа модели, промпт, провайдер
  files/         валидация и поэтапная загрузка
src/server/      Fastify: маршруты, сессии
src/worker/      цикл воркера и конвейер этапов
src/web/         React SPA
tests/           95 тестов
```

## Команды

```bash
npm run verify           # формат, линтер, типы, тесты, сборка — перед коммитом
npm test                 # только тесты
npm run migrate          # применить миграции
npm run pricelist:import # импорт прайса, см. README
```

## Работа с базой

Миграции только добавляются в `src/db/migrations.ts` новым элементом массива.
Уже применённую миграцию править нельзя — она не переприменится.

Деньги хранятся в копейках (INTEGER), объёмы — в тысячных долях (INTEGER).
Времена — миллисекунды Unix (INTEGER).

## Тесты

Мок модели допустим в unit-тестах. Он не является доказательством готовности:
интеграционные и e2e должны идти через настоящие маршруты и настоящий документ.

При изменении очереди обязательно прогоняйте `tests/job-queue.test.ts` — там
зафиксирована первопричина исходного дефекта.
