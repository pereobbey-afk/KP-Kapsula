# Методика расчёта объёмов «Капсулы»

Документ восстановлен по паре «дизайн-проект + смета» одного объекта:
квартира 1191, улица Академика Волгина, 78,06 м².

Все соотношения ниже **проверены построчной сверкой** расчёта с настоящей
сметой, а не выведены предположительно. Сверка воспроизводится командами
из раздела «Как проверить».

## Главный вывод

**Объёмы берутся из ведомостей проекта, а не выводятся из площади.**

Дизайн-проект содержит готовые сводные площади по каждому виду отделки.
Сметчик переносит их в смету напрямую. Поэтому расчёт «по площади и числу
комнат» не воспроизводит смету ни при какой калибровке коэффициентов:
состав и объёмы определяются проектными решениями, а не геометрией.

## Структура дизайн-проекта

Проект сделан в ArchiCAD, PDF **векторный с текстовым слоем** (не скан).
Текст в кодировке CP1251; при чтении как Latin-1 требуется перекодировка.
Это важно: ведомости читаются извлечением текста, без распознавания
изображений — быстрее, дешевле и точнее.

## Что это означает для правил расчёта

1. **Обои и покраска идут по одной площади и складываются.** Технология
   называется «Обои под покраску + покраска»: обои клеятся, затем
   красятся. Это не взаимоисключающие варианты.

2. **Малярный цикл идёт не по всей площади стен.** Стены делятся по видам
   отделки: под покраску, под плитку, под панели. Каждый вид имеет свою
   площадь в ведомости, и работы применяются только к своей.

3. **Гидроизоляция считается по площади плитки**, а не по площади мокрых
   зон: стены плюс пол под плиткой.

4. **Перегородка с шумоизоляцией — один пирог.** Каркас, рулонная
   звукоизоляция и два слоя ГКЛ идут по одной площади — площади
   шумоизоляции. Площадь гипсокартона из той же ведомости (14,28 м²)
   в смете не используется.

5. **Состав работ определяется проектом.** В этой смете нет штукатурки
   стен, стяжки и натяжного потолка — соответствующих решений нет в
   проекте. В смете другого объекта (70 м²) штукатурка есть, объём 226 м².
   Набор разделов нельзя задать константой.

6. **Площади отдельных помещений тоже используются.** Шумоизоляция
   потолка взята равной площади спальни, а не всей квартиры.

7. **Формат плитки и рисунок укладки — не мелочь.** Настенная плитка
   стоит от 6 500 до 25 480 ₽/м² в зависимости от формата, ламинат — от
   1 820 до 3 900 ₽/м² в зависимости от рисунка. Если решение в проекте
   не указано, работа уходит в «не включено», а не в смету с наугад
   выбранной позицией.

## Открытые вопросы

- **Подрозетники: 95 против 66.** Ведомость электроблоков перечисляет
  49 блоков, сумма рамок — 95 механизмов. В смете стоит 66 (и столько же
  коронений: 46 по ПГП плюс 20 по бетону). Расхождение — 29 механизмов,
  около 40 000 ₽. Либо смета считает не по ведомости, либо ведомость
  включает то, что в смету не идёт. Требуется ответ сметчика.
- **Бамбуковые панели: 64,18 против 63,74** (+0,44 м²). Похоже на
  ручную поправку на подрезку, но правило не подтверждено.
- **Позиция «Подготовка / уборка пола под покрытие» отсутствует
  в импортированном прайсе**: в исходном файле у неё не заполнена
  единица измерения, и импорт её отклонил. В смете она стоит с объёмом
  78,06 м² на 17 485 ₽. Нужно исправить прайс-лист.
- **Материалы.** Смета 70 м² содержит материалы (68 000 ₽, тип «мат»),
  смета 78 м² — нет. Правило включения материалов не установлено.
- Всё перечисленное восстановлено по **одному** объекту. Правила
  гидроизоляции, грунтовки и перегородок подтверждены единственным
  совпадением — на втором объекте их надо перепроверить.

## Роль ИИ и роль кода

ИИ читает проект и извлекает **исходные величины**: площади из ведомостей
и экспликации, количества из ведомостей розеток и светильников, длины из
планов. У каждой величины есть проверяемый источник — лист и строка.

Код детерминированно **выводит производные величины** по правилам выше
(гидроизоляция = плитка стен + плитка пола) и умножает объём на цену
активного прайса. Правила живут в `src/domain/estimate/derive.ts`,
ожидания зафиксированы в `tests/derive.test.ts` числами настоящей сметы.

Такое разделение сохраняет прежний барьер: модель не видит цен и не
считает деньги, а все арифметические связи проверяемы и покрыты тестами.

## Как проверить

Калибровка воспроизводится на любой паре «проект + смета»:

```bash
# 1. Прайс в отдельную базу
DATABASE_PATH=./data/calib.sqlite npm run migrate
DATABASE_PATH=./data/calib.sqlite npm run pricelist:import -- \
  --file "./prices/price_01.07.2026.xlsx:01.07.2026:2026-07-01" \
  --file "./prices/price_05.08.2026.xlsx:05.08.2026:2026-08-05" \
  --label "Прайс Капсула" --activate

# 2. Величины из ведомостей проекта
python3 scripts/calibration/parse_project.py проект_1191.pdf --json > /tmp/p.json

# 3. Расчёт и построчная сверка со сметой
DATABASE_PATH=./data/calib.sqlite npx tsx scripts/calibration/compare.ts \
  --project /tmp/p.json --estimate ./prices/смета_1191.xlsx
```

Разбору PDF нужен `pymupdf` (`pip install pymupdf`). Ключ API не нужен:
ведомости читаются текстом, без обращения к модели.
